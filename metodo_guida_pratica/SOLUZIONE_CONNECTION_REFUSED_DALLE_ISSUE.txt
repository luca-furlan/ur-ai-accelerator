================================================================================
🔧 SOLUZIONE "CONNECTION REFUSED" - BASATA SU ISSUE GITHUB
================================================================================

Issue GitHub #31: "Connection Refused" dopo configurazione normale
Link: https://github.com/UniversalRobots/Universal_Robots_ExternalControl_URCap/issues/31

================================================================================
📋 CAUSE COMUNI DI "CONNECTION REFUSED"
================================================================================

1. MACCHINA REMOTA NON IN ASCOLTO
   -------------------------------
   - Il robot cerca di connettersi alla macchina remota
   - Ma la macchina remota NON è in ascolto sulla porta 50002
   - SOLUZIONE: Avvia driver ROS2 PRIMA (mette macchina in ascolto)

2. FIREWALL BLOCCA PORTA
   ----------------------
   - Firewall sul PC blocca porta 50002
   - SOLUZIONE: Apri porta 50002 nel firewall
   - Comando: sudo ufw allow 50002

3. IP CONFIGURATO ERRATO
   ----------------------
   - Host IP sul Teach Pendant non corrisponde all'IP della macchina remota
   - SOLUZIONE: Verifica IP corretto (192.168.10.191)

4. ROBOT NON IN REMOTE CONTROL MODE
   ----------------------------------
   - Robot deve essere in Remote Control mode
   - SOLUZIONE: Abilita Remote Control sul Teach Pendant

5. DOCKER SENZA --network=host
   ----------------------------
   - Se ROS2 gira in Docker, serve --network=host
   - SOLUZIONE: Avvia Docker con --network=host

6. PORTA GIÀ IN USO
   -----------------
   - Un altro processo usa già porta 50002
   - SOLUZIONE: Chiudi altri processi che usano porta 50002

================================================================================
✅ SOLUZIONE PASSO-PASSO
================================================================================

PASSO 1: VERIFICA MACCHINA REMOTA IN ASCOLTO
---------------------------------------------
Dalla macchina remota:
ssh lab@192.168.10.191
netstat -tuln | grep 50002

Dovresti vedere: "0.0.0.0:50002" in LISTEN

Se NON vedi questo:
- Avvia driver ROS2 PRIMA:
  cd ~/MekoAiAccelerator/metodo_guida_pratica
  ./START_RAPIDO.sh

PASSO 2: VERIFICA FIREWALL
---------------------------
Dalla macchina remota:
sudo ufw status

Se firewall attivo:
sudo ufw allow 50002
sudo ufw reload

PASSO 3: VERIFICA IP CORRETTO
------------------------------
Sul Teach Pendant, nel nodo External Control:
- Host IP: 192.168.10.191 (IP della MACCHINA REMOTA)
- Porta: 50002

PASSO 4: VERIFICA REMOTE CONTROL MODE
-------------------------------------
Sul Teach Pendant:
- Settings → System → Remote Control
- Deve essere "Enabled"

PASSO 5: VERIFICA PORTA NON IN USO
-----------------------------------
Dalla macchina remota:
sudo lsof -i :50002

Se vedi altri processi:
sudo kill -9 <PID>

PASSO 6: AVVIA PROGRAMMA SUL ROBOT
-----------------------------------
Sul Teach Pendant:
1. STOP programma (se è in esecuzione)
2. Verifica configurazione External Control:
   - Host IP: 192.168.10.191
   - Porta: 50002
3. PLAY programma
4. Il robot si connetterà alla macchina remota

================================================================================
🚨 SE ANCORA NON FUNZIONA
================================================================================

PROVA CONFIGURAZIONE ALTERNATIVA:
----------------------------------

Sul Teach Pendant, prova con Host IP VUOTO:
- Host IP: (LASCIA VUOTO o 0.0.0.0)
- Porta: 50002

Questa configurazione fa sì che:
- Il robot ASPETTA connessioni invece di connettersi
- Il driver ROS2 si connette AL robot

Poi avvia programma sul robot e verifica porta aperta:
ssh lab@192.168.10.191
nc -zv 192.168.10.194 50002

Se vedi "Connection succeeded!", funziona!
