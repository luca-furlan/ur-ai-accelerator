================================================================================
COMANDI FIX SSH - SENZA UFW (solo IPTABLES)
================================================================================

Esegui questi comandi direttamente sulla macchina AI Accelerator:

--------------------------------------------------------------------------------
1. PERMETTI SSH IN IPTABLES
--------------------------------------------------------------------------------

sudo iptables -I INPUT -p tcp --dport 22 -j ACCEPT

# Verifica che la regola sia stata aggiunta:
sudo iptables -L INPUT -n | grep "22"


--------------------------------------------------------------------------------
2. VERIFICA CONFIGURAZIONE SSH (ListenAddress)
--------------------------------------------------------------------------------

# Controlla se SSH ascolta solo su localhost
sudo grep "ListenAddress" /etc/ssh/sshd_config

# Se mostra "ListenAddress 127.0.0.1" o simile, FIXA:
sudo sed -i 's/^ListenAddress.*/#ListenAddress 0.0.0.0/' /etc/ssh/sshd_config

# Se non c'è ListenAddress, va bene (default: tutte le interfacce)


--------------------------------------------------------------------------------
3. ABILITA PASSWORD AUTHENTICATION
--------------------------------------------------------------------------------

# Verifica
sudo grep "PasswordAuthentication" /etc/ssh/sshd_config

# Se è "no", abilita:
sudo sed -i 's/^PasswordAuthentication no/PasswordAuthentication yes/' /etc/ssh/sshd_config


--------------------------------------------------------------------------------
4. RIAVVIA SSH
--------------------------------------------------------------------------------

sudo systemctl restart ssh

# Verifica che sia attivo
sudo systemctl status ssh


--------------------------------------------------------------------------------
5. VERIFICA FINALE
--------------------------------------------------------------------------------

# Verifica porta 22 in ascolto su 0.0.0.0 (non solo 127.0.0.1)
sudo ss -tlnp | grep :22

# Dovrebbe mostrare:
#   LISTEN  0  128  0.0.0.0:22  0.0.0.0:*  users:(("sshd",pid=...,fd=...))

# Se mostra 127.0.0.1:22 invece di 0.0.0.0:22, quello è il problema!


--------------------------------------------------------------------------------
6. SALVA REGOLE IPTABLES (opzionale, per persistenza)
--------------------------------------------------------------------------------

# Crea directory se non esiste
sudo mkdir -p /etc/iptables

# Salva regole
sudo iptables-save | sudo tee /etc/iptables/rules.v4

# Per caricare al boot, aggiungi a /etc/rc.local o crea servizio systemd


================================================================================
COMANDI RAPIDI (tutti insieme)
================================================================================

# Copia e incolla tutto:

sudo iptables -I INPUT -p tcp --dport 22 -j ACCEPT
sudo sed -i 's/^ListenAddress.*/#ListenAddress 0.0.0.0/' /etc/ssh/sshd_config
sudo sed -i 's/^PasswordAuthentication no/PasswordAuthentication yes/' /etc/ssh/sshd_config
sudo systemctl restart ssh
sleep 2
echo "=== VERIFICA ==="
sudo ss -tlnp | grep :22
sudo systemctl status ssh --no-pager | head -5


================================================================================
SE ANCORA NON FUNZIONA
================================================================================

1. Verifica che SSH ascolti su 0.0.0.0 (non 127.0.0.1):
   sudo ss -tlnp | grep :22
   # Deve mostrare 0.0.0.0:22, NON 127.0.0.1:22

2. Verifica IPTABLES non blocca:
   sudo iptables -L INPUT -n -v | grep 22

3. Test locale:
   ssh lab@localhost
   # Dovrebbe funzionare

4. Verifica log SSH:
   sudo journalctl -u ssh -n 50 | grep -i "error\|refus\|deny"

5. Controlla se c'è un altro firewall:
   sudo systemctl list-units | grep -i firewall
